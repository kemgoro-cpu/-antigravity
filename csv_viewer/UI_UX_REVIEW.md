# UI/UXレビューと改善記録

実施日: 2026-09-28。対象: CSV Chart Viewerの現在の比較ワークスペース。
WindowsのMicrosoft Edgeを独立したブラウザプロファイルで起動し、`file://`で検証した。
元のCSVや通常ブラウザの保存データは変更していない。

## 判断と変更

初期画面では比較準備・多数のツール・3段階の案内が同時に見え、読み込み後も次の操作が明確にならなかった。
特に狭い画面で、左パネルと右パネルが波形より広い領域を占有していた。
波形の領域を確保し、必要なパネルを自分で開ける配置にした。計算定義やチャンネルの自動選択は変えていない。

## 2026-10-29: 再読み込み時のResizeObserverエラーの調査と修正

状態: **DONE**。調査は `investigate` の手順で行い、再現と原因の確認後に修正した。

### 症状と原因

再読み込み直後に「予期しないエラー / ResizeObserver loop completed with undelivered notifications.」が表示されるとの報告。
保存された左パネルの幅を復元するとツールバーが折り返し、チャート領域の高さが減る。
古い大きさのキャンバスには一時的に縦スクロールバーが現れ、監視通知中の同期 `chart.resize()` がこれを消す。
その結果、監視中のコンテナの有効幅が同じ通知の配信中に変化し、ブラウザが上記のエラーを発行していた。

Edge、1366×700、2ログ・3チャンネル、統計表示、左パネルをEndキーで820pxへ拡張して保存後に再読み込みすると自然に再現した。
同期コールバック中の計測では、幅が535→541px、続いて175→181pxへ変わり、スクロール高さは500→416→302pxへ減少した。
6pxの幅差は同梱CSSのスクロールバー幅と一致する。

### 修正内容

`compare-workspace.js` のサイズ監視では、再描画を1つの `requestAnimationFrame` に予約する。
チャート・ナビゲーター・時間合わせプレビューのリサイズは次のフレームでまとめて行い、監視通知の配信中にサイズを書き換えない。
内部ズームの対象、`hideTip` の順序、ナビゲーター1つへの統一は維持している。

### 再発検出と検証結果

- 新しい `tests/resize-observer.browser.js` は、通常のUI操作と保存済み設定の再読み込みで再現する。ResizeObserverやレイアウト処理のモック、エラーの人工的な発火は使っていない。
- Playwrightのheadless既定引数 `--hide-scrollbars` を外す。以前の検証環境では実際のスクロールバー幅の変化が隠れていた。
- 読み込み前から `window.error` を記録する。ブラウザ生成のResizeObserver通知は `pageerror` に届かないため、以前の `pageerror` だけの確認では拾えていなかった。
- 修正前: 自然な再読み込みで信頼されたブラウザエラーが1〜2件発生し、新テストは失敗。`pageerror` は0件のまま。
- 修正後: 新テストが成功。保存済み左パネル幅の復元、手動チャート高さ、大きいフォント、統計表示、1365／1100／390px幅での再読み込みと比較パネル開閉で `window.error` 0件、描画サイズとDOMサイズの一致を確認。
- 独立した元の再現用プローブでも、修正後の連続2回の再読み込みで警告0件を確認。
- `npm test`: 既存の単体テスト8本が成功。`ux-layout.browser.js` と `ux-comparison.browser.js` も成功。
- `ux-layout.browser.js` は画面幅変更後のメディアクエリー処理完了を待ってから左パネル幅を測るよう補正。16pxのキーボード幅変更という検証条件は維持した。

再実行はPlaywrightとEdgeを利用できる環境で `node tests/resize-observer.browser.js`。
修正前のエラーと修正後の画面は `tests/fixtures/generated/resize-observer-2026-10-29/` に保存した（Git対象外）。

## 2026-10-29: 許容差を超えた箇所の表示と移動

### 実装した機能

- 比較結果の先頭に超過した項目数を表示し、各カードに「許容差超過」などの判定を明示。初期の並べ替えは超過度順とし、チャンネル順へも切り替えられる。
- オレンジの帯は基準ログの連続する超過サンプルの最初〜最後、縦線は単発の超過サンプル。欠損・範囲外・許容差以下の点で区間を分断する。
- 「最初の超過へ」「前へ／次へ」で各区間へ移動。結果や元の評価区間を保持し、移動中に許容差を変更しても元の区間を再評価する。「比較を更新」は現在の選択／表示区間を評価する。
- 上下比較では該当する比較ファイルの段だけを強調し、重ね合わせ・差分でもチャンネルと比較ファイルを対応させる。既存のイベント帯・選択区間は別の系列として維持する。
- 時間範囲・選択チャンネル・信号対応・時間差・元時刻表示・Bit扱い・計算式・時間単位の変更後は古い判定と帯を解除。Y軸だけのズームと表示方式の変更では有効な結果を維持する。
- メモに許容差を記録し、画像には計算後の帯を含める。保存容量を増やさないよう、再計算できる区間配列はメモの結果から除外する。

### 判定の意味と検証範囲

判定対象は従来どおり `|基準 − 比較| > 許容差`。等値は超過ではない。
線形補間・Bitの直前値保持・最大差・平均差・RMS差・有効／欠損点数・状態不一致時間の計算は変更していない。
区間の端は実際に超過を確認した基準サンプルの時刻であり、連続時間の正確な境界や超過秒数を示すものではない。
有効点なし、未対応、単位不一致、許容差未設定を正常とは表示せず、欠損のある許容差内の結果も完全な判定と区別する。

`tests/compare-utils.test.js` は不規則な時刻、等値、両側の欠損、孤立点、最大値の同値、評価区間端、シフトと補間方式を確認し、区間配列を追加しても既存の数値指標が変わらないことを照合する。
`tests/comparison-tolerance.browser.js` は3ログを使用し、5点の超過を2〜3秒・単発6秒・8〜9秒として表示すること、前後移動、閾値の変更、複数ファイルと表示方式の対応、古い着色の解除を確認する。
ダーク／ライトの1600px画面で、帯・単発線・超過表示を目視確認した。

最終検証は `npm test` の既存8本が成功。ブラウザは `comparison-tolerance.browser.js`、`comparison-interactions.browser.js`、`ux-comparison.browser.js`、`ux-layout.browser.js`、`resize-observer.browser.js` の5本が成功した。
新テストでは実際の計算式編集と秒／msの訂正による解除も確認し、ネイティブの `window.error` とJavaScript例外はいずれも0件だった。
