# UI/UXレビューと改善記録

実施日: 2026-09-28。対象: CSV Chart Viewerの現在の比較ワークスペース。
WindowsのMicrosoft Edgeを独立したブラウザプロファイルで起動し、`file://`で検証した。
元のCSVや通常ブラウザの保存データは変更していない。

## 判断と変更

初期画面では比較準備・多数のツール・3段階の案内が同時に見え、読み込み後も次の操作が明確にならなかった。
特に狭い画面で、左パネルと右パネルが波形より広い領域を占有していた。
波形の領域を確保し、必要なパネルを自分で開ける配置にした。計算定義やチャンネルの自動選択は変えていない。

| 優先度 | 確認した問題 | 実装した改善 | 検証・証拠 |
| --- | --- | --- | --- |
| 高 | 390px画面で波形領域が175px幅になり、比較パネルも重なって操作困難 | 左パネルを引き出し式へ変更。比較パネルは狭い画面で初期非表示、内部に閉じるボタン | 前後の`loaded-390.png`、`ux-layout.browser.js` |
| 高 | ファイル削除・全消去はUndoも復元データも消すのに1クリックで実行 | 対象名・件数・失われる状態を明示し、キャンセルを初期フォーカスにした確認ダイアログ | `ux-interactions.browser.js`でEsc/キャンセル/確定、半角カナ名、フォーカス復帰 |
| 高 | パネル切替・チャンネル変更で入力中のメモや未適用対応が消える | DOMから下書き状態を分離。メモ・テンプレ名・ファイルごとの対応候補・時間合わせ入力を保持 | `ux-comparison.browser.js`で切替前後の文字列と未適用状態を確認 |
| 高 | 非同期の比較中に区間を変えると古い結果が後から表示される | 計算ごとの識別子で更新を管理し、区間・Bit・対応等の変更時に結果を破棄 | `ux-comparison.browser.js`で計算中の区間変更、更新表示、再計算を確認 |
| 高 | メモ保存中の条件変更や連打で、画像・条件・数値の不整合や重複が生じる | 保存中表示と連打防止、条件スナップショットの一致確認。失敗時は下書きを残す | `ux-comparison.browser.js`で競合中の保存0件、連打時1件 |
| 中 | 1100pxの初期案内がナビゲーターの下に切れる | 1つの開始操作へ簡素化し、読み込み後はチャンネル選択へ案内を切替 | 前後の`empty-1100.png`、3画面幅で案内全体の座標検証 |
| 中 | ツールがアイコンのみになり、名称を毎回探す必要がある | 主操作の文字を残す。高さ調整を「表示」へ、一括クリアを左パネルへ移動 | 前後の`loaded-1100.png`、主操作ラベルの可視性検証 |
| 中 | 検索0件が英語だけで、絞り込み解除が見つからない | 日本語の案内、件数、検索文字のクリア、絞り込み解除、`/`・`Ctrl+K` | `ux-layout.browser.js`で検索→0件→復帰、選択済みフィルター解除 |
| 中 | ファイル・Bit・対応・式挿入が非ボタン要素で、操作後のフォーカスも失われる | ネイティブボタンと名前を付与、再描画後のチャンネルフォーカス維持、式入力欄を開いてから移動 | `ux-interactions.browser.js`でキーボードのみの選択・移動・対応・挿入 |
| 中 | 表示設定でTabがメニューを閉じ、selectの矢印キーを奪う。解析ツール中にBが波形へ漏れる | 設定フォームとコマンドメニューのキー処理を分離。開いた解析メニュー中の波形ショートカットを抑制 | `ux-interactions.browser.js`でTab・矢印・Escape・B |
| 中 | 区間選択のキャンセル後も通常ズームが区間選択として動く | 区間選択モードの終了処理を統一し、ボタン状態とEscを連動 | `ux-comparison.browser.js`でEsc→B→通常ズーム、ボタンによるキャンセル |
| 中 | 開始時刻の空欄を0秒として扱う | 両欄の必須確認とEnterによる実行。空欄では表示範囲を変更しない | `ux-comparison.browser.js`で空欄時刻を確認 |
| 中 | キーボード用ヘルプのアイコンが空白、ライトテーマのダイアログが暗い、ファイル名が操作ボタンに押される | 同梱フォントに存在するアイコン、テーマ変数、ファイル名と操作の行分け | `ux-layout.browser.js`とライト/ダークの画面確認 |
| 中 | 狭い画面だけで「Y軸が多い」という誤った対処案内 | 複数のY軸がある場合だけ、軸共有の案内を表示 | 390pxの単軸2段表示で誤警告がないことを確認 |

## レイアウトの実測

同じ画面幅でのDOM測定。チャート領域はコンテナー全体であり、軸やスライダーを除いた実プロット面積ではない。
改善前は同梱NEDCサンプル、改善後は小さな合成CSVを使い、いずれも2ファイル・2つの明示選択チャンネルで確認した。

| 画面 | 改善前の幅 | 改善後の幅 | 状態 |
| --- | ---: | ---: | --- |
| 1100×800 | 525px | 835px | 比較パネルは必要時に開く |
| 390×844 | 175px | 390px | 左右のパネルを閉じて波形を表示 |

390×844ではチャート高さも213pxから449pxへ増え、ツールバー高さは259pxから123pxへ減った。
1600×1000では左右パネルを表示したまま935×708pxのチャート領域を確保した。
「どんな画面でも最適」の証明ではなく、上記条件での測定結果である。

## 検証

- 単体テスト8本: parser / settings / history / layout / drive-index / chart-options / compare / xy。
- 既存ブラウザテスト7本: comparison / comparison-interactions / comparison-generated / comparison-edge / comparison-multifile / comparison-remap / comparison-restore-order。
- 新規ブラウザテスト3本: ux-layout / ux-interactions / ux-comparison。
- 既存の合成データで3・4・5・10ファイルの比較、大容量5ファイル（合計500,005時刻点）、単位違い・欠損値・周期違い、Main切替、再起動復元、Undo/Redoを確認。
- 新規UIテストでは、実ファイルとDataTransferによるドロップ、半角カナを含む名前、表示名、キーボード、パネルのフォーカス制御、競合中の入力とメモ保存を検証。
- すべて独立プロファイルの`file://`起動。ブラウザ検証で未処理JavaScriptエラーなし。

画面操作の試験では2つの座標依存を修正した。時間合わせの試験は、枠の境界ではなく実際のcanvas座標でクリックするよう変更した。
また、ドラッグ中の案内で波形が押し下げられる回帰を発見し、案内をレイアウトに影響しない表示へ直した。
単にテスト期待値を弱める変更はしていない。

### 再実行

PlaywrightとMicrosoft Edgeを利用できる開発環境で、`csv_viewer`を作業ディレクトリにする。
アプリ本体には追加ランタイムやネットワーク接続は必要ない。

```text
npm test
node tests/comparison.browser.js
node tests/comparison-interactions.browser.js
node tests/comparison-generated.browser.js
node tests/comparison-edge.browser.js
node tests/comparison-multifile.browser.js
node tests/comparison-remap.browser.js
node tests/comparison-restore-order.browser.js
node tests/ux-layout.browser.js
node tests/ux-interactions.browser.js
node tests/ux-comparison.browser.js
```

画面と測定値は`tests/fixtures/generated/ux-audit-before/`と`ux-audit-after/`に保存した（生成物としてGit対象外）。
改善前はGitのHEADを別の一時フォルダーへ書き出した固定ソースで再取得し、変更後の画面と混在しないよう確認した。
変更後の画面は`ux-layout.browser.js`で再生成でき、`UX_SCREENSHOT_DIR`で出力先を変更できる。

## リファクタリングと残る確認

`workspace-ui.js` / `workspace-ui.css`へ画面の導線・開閉・検索・配置を切り出した。
比較パネルでは入力中の状態と計算の有効性を、再生成されるDOMから分離した。
共通ダイアログに終了処理を集約し、Escなどで閉じた場合も待機中の処理が終了するようにした。
旧Auto Alignダイアログも共通化したが、通常導線は比較パネルを使うため、これはフォールバック経路の保守改善である。

未実施: 実際の利用者による作業時間・操作ミス率の測定、実機のタッチ操作、スクリーンリーダーでの読み上げ、Edge以外のブラウザ確認。
アクセシビリティの正式な適合評価ではない。次の実務確認では、普段のログを使い「読み込み→検索→時間合わせ→差分確認→メモ付き出力」を行い、迷った箇所と完了時間を記録すると改善効果を確認できる。
