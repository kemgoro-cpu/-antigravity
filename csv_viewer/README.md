# CSV Chart Viewer

CSV / TRN ファイルをブラウザだけで読み込み、複数チャンネルの時系列データをインタラクティブに可視化する Web アプリです。依存ライブラリは `lib/` に同梱しているため、インターネット接続なしで動作します。

## 起動方法

`index.html` をブラウザで開きます。ローカルサーバーは不要です。

```text
csv_viewer/
├─ index.html
├─ app.js              … メインロジック
├─ parser-utils.js     … CSVパース・文字コード判定（Nodeテスト可能な純粋関数）
├─ settings-utils.js   … 設定のバージョンチェック・マイグレーション（同上）
├─ history-utils.js    … Undo/Redo統合履歴のロジック（同上）
├─ layout-utils.js     … フォントプリセット・グリッド高さ配分（同上）
├─ chart-options-utils.js … チャートのEChartsオプション構築ヘルパー（同上）
├─ drive-index-utils.js … ドライビングインデックス（走行モード判定）のロジック（同上）
├─ drive-cycles-data.js … 標準走行モード（NEDC / WLTC Class 3a・3b / MDC）の目標車速データ
├─ styles.css
├─ package.json        … npm test 用（依存ライブラリなし）
├─ scripts/
│   ├─ run-tests.js       … 全テストを順次実行するランナー（npm test の実体）
│   └─ generate_nedc.js   … NEDCサンプルTRN生成スクリプト（開発用）
├─ tests/              … Nodeで実行する単体テスト
└─ lib/                … 同梱ライブラリ（ECharts, PapaParse等）
```

変更履歴と引き継ぎ用の注意点は [CHANGELOG.md](CHANGELOG.md) を参照してください。

## CSV / TRN の読み込み

サイドバーの Files エリアへ `.csv` または `.trn` ファイルをドラッグ&ドロップするか、Browse Files から選択します。最初に読み込んだファイルが Main、追加ファイルが Sub として扱われます。

想定 CSV 形式:

```csv
Time,RPM,Torque,Speed
s,rpm,Nm,km/h
0.000,1500,45.2,0.0
0.001,1502,45.3,0.1
```

- 1 行目: チャンネル名
- 2 行目: 単位
- 3 行目以降: 数値データ
- `Time` または `時間` を含む列を時間軸として検出します
- 時間単位が `ms` / `msec` / `sec` / `s` の場合は秒へ自動変換します
- 複数ファイル読み込み時、Time 単位が未記載でも時間幅が 1000 倍程度違う場合は `ms` / `sec` を自動推定します
- 自動判定が違う場合は、Files一覧の `Time` セレクトでファイルごとに `s` / `ms` を手動指定できます

ヘッダー行が異なるファイルでは、Settings の Name Row / Unit Row を変更してから読み込んでください。

## 文字コード

Settings の Encoding で読み込み文字コードを指定できます。

- `Auto`: UTF-8 / Shift_JIS / UTF-16 の BOM や先頭バイト列から自動判定
- `UTF-8`: UTF-8 固定
- `Shift_JIS`: Excel や計測器由来の CP932 / Shift_JIS CSV 向け
- `UTF-16LE` / `UTF-16BE`: UTF-16 CSV 向け

読み込み後はサイドバーの Parse Preview とファイル一覧バッジに判定された文字コードが表示されます。日本語のチャンネル名や単位が文字化けする場合は、Encoding を `Shift_JIS` に固定して再読み込みしてください。

## 読み込み状態とエラー

読み込み中は Files セクションに処理中のファイル名、フェーズ、処理行数が表示されます。時間データや選択チャンネルの読み込みは、右側の X ボタンでキャンセルできます。

ヘッダー行、Time 列、データ開始行、数値データに問題がある場合は、原因と確認ポイントをトースト通知で表示します。

## 主な機能

- チャンネル一覧から表示 / 非表示を切り替え
- チャンネル名検索
- チャンネルごとの Y 軸 min / max 指定
- 複数ファイルの重ね合わせ表示
- Sub ファイルの Time Shift 手動調整
- 複数ファイル間の Time 単位自動調整
- ファイルごとの Time 単位手動補正と設定保存
- Auto Align による時系列位置合わせ
- Y 軸ラベルのドラッグで3本以上のチャンネルを同一チャートへ重ね合わせ
- 同じ単位は同じY軸へ自動配置し、異なる単位は共有軸または新規軸を選択
- Arrange モードで描画中のチャート順を上下に並べ替え
- Bit チャンネルの自動検出と表示切り替え
- Custom RAM による計算チャンネル追加
- LTTB サンプリングによる大容量データの高速描画
- PNG 保存、クリップボードコピー
- 設定の JSON エクスポート / インポート
- Settings セクションで設定プリセットを保存 / 適用 / 削除
- Undo / Redo（Ctrl+Z / Ctrl+Y / Ctrl+Shift+Z、ツールバーボタン）。ズーム・チャンネル選択・マージ・Custom RAM・色変更などの操作を時系列順に戻せる。ファイル追加 / 削除 / Clear All / Time 単位変更の時点で履歴はリセットされる
- チャートの縦幅調整: ツールバーの `Fit / − / ＋` で全体を段階調整（入りきらない分は縦スクロール）。グリッドの下端境界をドラッグすると個別に高さ変更でき、境界のダブルクリックでそのチャートだけ自動に戻る
- チャートのフォントサイズ: ツールバーで 小 / 標準 / 大 / 特大 を選択（チャンネル名・軸の数値・ホバー値が連動）。長いチャンネル名はチャート高さに収まらない分が「…」で自動省略される
- Channel Map で、名前が違うSub側チャンネルをMainチャンネルへ対応付け
- ライト / ダークテーマ切替（ツールバー右の太陽 / 月アイコン。選択は保存される）
- カーソル計測（ツールバーの Measure、ショートカット M）: チャートを2回クリックすると、区間の Δt と表示チャンネルごとの A / B / Δ / min / max / mean / RMS をパネル表示。Esc で解除
- イベント検出（サイドバーの Events）: 条件式（例 `Actual_Speed > 120`）を満たす区間を検出して一覧表示+チャート上をハイライト。行クリックで該当区間へズーム
- セッション自動復元: 読み込んだファイルはブラウザ（IndexedDB）に保存され、次回起動時に選択状態ごと自動復元される（ファイル削除 / Clear All で保存も消える。合計200MBまで）
- 表示範囲の統計サマリ（ツールバーの Stats）: 見えている範囲の min / max / mean / σ をズームに追従して表示
- 表示データの CSV エクスポート（ツールバーの CSV）: 表示中の時間範囲 × 表示チャンネル（Custom RAM の計算結果を含む）を CSV 保存
- XY プロット（ツールバーの XY）: 任意チャンネル同士の散布図（例: 車速 vs 燃料流量）。main / sub 重ね描き、表示中の時間範囲との連動
- 差分カーブ生成（ツールバーの Diff、Sub があるとき）: Main と Sub の同名チャンネルから選んで Main − Sub の差分を Custom RAM として一括生成
- HTML レポート出力（ツールバーの Report）: チャート画像・ファイル情報・統計・Drive Index・Custom RAM・イベント一覧を1枚の HTML に保存
- チャンネルセットのお気に入り（Channels の ★）: よく見るチャンネルの組み合わせを保存してワンクリック適用（Clear All でも消えない）

## Custom RAM

既存チャンネルの四則演算や関数で、新しいチャンネルを追加できます。作成時に任意の単位を指定でき、作成後も一覧の編集アイコンから変更できます。

例:

```text
RPM / 60
Torque * RPM * 3.14159 / 30
sqrt(pow(X, 2) + pow(Y, 2))
SPD > 60 && GEAR == 4
```

Sub ファイルのチャンネルは `s1:チャンネル名` の形式で参照できます。
比較（`> < >= <= == !=`）と論理（`&& ||`）も使えます（結果は 1 / 0 の系列。イベント検出の条件式と同じ文法）。使える関数と演算子の一覧は Custom RAM 見出し横の「?」から確認できます。

### 走行モードの目標車速チャンネル（`@MDC` など）

Drive Index が走行モードを判別すると、そのモードの目標車速がチャンネルとして自動で追加されます（`@MDC` / `@NEDC` / `@WLTC3b_3` など、単位 km/h）。チャンネル一覧でクリックすればグラフに重ねられます。

- 実測ログの整合位置に合わせて配置されるので、実測車速とそのまま重なります。モード区間の外（計測前後の余分なデータ）には線を引きません。
- Main / Sub それぞれのファイルの時間軸に合わせて作られます。
- Custom RAM の式からも参照できます。例えば `Actual_Speed - @MDC` で追従誤差の波形が得られます。
- 判別結果から毎回作り直されるため、走行モードを切り替えると中身も名前も入れ替わります。目標車速に CSV の列を指定した場合は作られません。

## チャート配置と複数Y軸

- ツールバーの Arrange を有効にすると、チャート枠を上下ドラッグして表示順を変更できます。
- 通常モードで単独チャートのY軸ラベルを別チャートへドラッグすると、同じ枠へ重ねられます。
- 同じ単位のY軸があれば自動共有します。異なる単位や単位なしの場合は、既存軸の共有または新しいY軸を選択します。
- 重ね合わせたチャートのY軸ラベルをダブルクリックすると、軸割り当ての変更やチャンネルの分離ができます。

## デバッグ

ファイル一覧の虫眼鏡アイコンから Parse Info を開くと、検出された文字コード、ヘッダー行、Time 列、Time 単位の判定結果、列一覧、読み込みプレビューを確認できます。

## 設定プリセット

Settings セクション下部のプリセット操作で、現在のヘッダー行、文字コード、サンプリング、Custom RAM、選択チャンネル、Y 軸範囲などをブラウザに保存できます。同じ形式のログを繰り返し見るときに使います。

- 保存: ディスクアイコン
- 適用: 再生アイコン
- 削除: ゴミ箱アイコン

## Channel Map

Main と Sub で同じ物理値なのにチャンネル名が違う場合、Channels 一覧のリンクアイコンから別名を登録できます。

例: Main の `車速` に対して Sub 側の `Vehicle Speed` を登録すると、`車速` を選択したときに Sub の `Vehicle Speed` も同じグリッドへ重ね描画されます。候補は単位一致や名前の近さで並びますが、自動では適用されません。

登録した対応表は通常設定、設定JSON、プリセットに保存されます。

## 開発メモ

ブラウザ不要のユーティリティテスト（全6本: parser / settings / history / layout / chart-options / drive-index）は
`csv_viewer/` で次のコマンドを実行すると一括で走ります（1本でも失敗すると非0終了）。

```bash
npm test
```

従来どおり `node tests/<name>.test.js` で1本ずつ実行することもできます
（parser-utils / settings-utils / history-utils / layout-utils / chart-options-utils / drive-index-utils）。

構文チェック:

```bash
node --check app.js
node --check parser-utils.js
node --check settings-utils.js
node --check history-utils.js
node --check layout-utils.js
node --check chart-options-utils.js
node --check drive-index-utils.js
node --check drive-cycles-data.js
```

同梱サンプル `NEDC_sample_A/B/C.trn` は `node scripts/generate_nedc.js` で再生成できます。
乱数はシード固定（mulberry32）のため出力は決定的で、何度実行しても同じ内容になります。
出力先は省略時 `csv_viewer/` 直下（コミット済みサンプルを上書き）で、
`node scripts/generate_nedc.js <出力ディレクトリ>` で変更できます。

設定の保存形式（`_version`）を変更するときは、`settings-utils.js` の
`SETTINGS_VERSION` とマイグレーション処理、テストを必ずセットで更新してください。

### UI文言の言語ポリシー

- **ユーザー向けメッセージ（トースト・モーダル・検証メッセージ・確認ダイアログ）は日本語が主言語。**
  新しいメッセージを追加するときは日本語で書くこと。
- **ツールバー等の短い操作ラベル（Clear All / Box Zoom / Save PNG / Fit 等）は
  計測ツールの慣習として英語を維持する。**
- エラートーストの詳細欄に載せる技術情報（例外メッセージ・ファイル名・スタック等）は
  原文のまま表示してよい。
- メッセージカタログ（`messages.js` 等）への全文字列集約は、翻訳・多言語化の要件が
  出るまで実施しない（文字列の大半がテンプレートリテラルで状態と密結合しており、
  現時点では抽出コストとリグレッションリスクが利益を上回るため）。

チャートのテーマ色は `styles.css` の `:root` トークンが単一情報源。
EChartsはCSS変数を解釈しないため、app.js 起動時に `cssVar()`（`T` 定数の構築）で
実値へ解決している。`--bg-main` 等を変更するとチャート・PNG出力の背景も追従する。
